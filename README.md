# 投籃簿

用 iPhone 或電腦瀏覽器紀錄練投的進球、未進、待確認球數與命中率。支援相機即時計數、選擇性錄影、影片匯入、逐球回看與修正、CSV / JSON 匯出。

網頁入口：<https://ianpy91g.github.io/basketball/>

GitHub Pages 版在使用者裝置內處理相機與匯入影片，不傳送影像到伺服器。原始影片、個人筆記、分析輸出與錄影檔不包含在程式儲存庫或部署產物中。

## iPhone 使用

1. 用 Safari 開啟上方 HTTPS 網址。
2. 點「開啟後置相機」，允許網站使用相機。
3. 橫放並固定手機，清楚拍到籃圈、籃網與球的飛行路徑。
4. 點「設定籃圈與球場」。在同一個設定面板框住橢圓形籃圈，再加入看得見的球場／人物參考點；不需拍到中場線。
5. 按「完成設定」，再點「開始練投」。若要估計出手位置，請勾選「同時錄影」。
6. 結束後會沿用開始前的設定，使用錄影接續估計各球位置。逐球複核，需要保存時匯出統計，並另按「儲存錄影」。

可使用 Safari 的「加入主畫面」建立入口。首次開啟、重新載入與取得更新需要網路；目前未提供離線快取。拍攝時保持頁面在前景，切到其他 App 或鎖定螢幕會停止分析。

統計與修正最多保存最近 10 次在目前瀏覽器的 localStorage；不會隨 GitHub 帳號同步，也不保存錄影。清除網站資料會清除這些本機統計。

## 影片分析

網頁版：切到「影片分析」，匯入 Safari / 瀏覽器能播放的 MP4 或 MOV。先按「設定籃圈與球場」，在同一個面板完成籃圈、球場與人物參考，按「完成設定」後才會啟用「開始分析」。按一次開始後，程式會先統計進／未進，再自動接續位置估計。能否播放取決於影片編碼與裝置支援。

MTS / M2TS 需使用電腦本機版本轉檔，GitHub Pages 不執行 Python 或 FFmpeg。

## 逐球回看

v2.2 將影片與逐球清單放在同一個工作區。桌面左右並排，手機上下排列；逐球清單獨立捲動，選球不會將整個頁面捲到影片位置。球的軌跡使用純亮橘色，不加描邊或陰影；框選中的籃圈與確認後的籃圈標記都使用深藍色。

- **單球循環**：點一球後重複播放該球片段，直到換球或暫停。
- **依序播放**：自動接續下一球片段；播完最後一球會暫停，可按「從頭播放」再看一次。標成忽略的事件不會自動排入序列。
- **單球一次**：播完目前片段後暫停。也可以用上一球、下一球按鈕選擇。

片段以到框時間前後擷取，密集出手時以相鄰投籃的中間時間分開。手動拖曳影片進度到片段外，可自由播放整支影片；再選一球即可恢復片段回看。整體命中率、CSV / JSON 匯出與練習紀錄移到下方預設收起的區域。

## 投籃位置圖與分析前設定（v2.6）

這一版採用**人工地標校正與自動出手位置估計**，也保留人工定位和修正。影片與位置圖維持同一工作區，不會因為選球跳動整個頁面。

1. 載入影片或開啟相機後，按「設定籃圈與球場」。尚未有投籃紀錄時即可設定。
2. 用「① 框選籃圈」拖曳框住橢圓形籃圈，再用「② 球場／人物參考點」加入地面對應。固定地標是先選圖上編號，再點影片同一位置；人物／自訂地面點是先影片、再球場圖。左右以球場圖為準。
3. 點幾個就用幾個，配對完按「完成設定」。可加入全部看得到的地標；「退回一點」與「清空點」只修改草稿，「取消設定」會還原籃圈、球場與場地模式。球場點可略過，仍須框好籃圈並明確完成整組設定。
4. 按「開始分析」後，程式使用同一組設定接續完成進／未進統計與位置估計。完成設定本身不會啟動分析或位置掃描。首次定位須下載姿態模型；可按「停止定位」保留計數與已完成的位置，之後用「自動抓所有出手位置」重試。
5. 自動位置標為「待複核」。選球回看，可按「確認此球位置」，或用影片腳下位置／球場圖重新標記。圖上橘色圓點代表進球、藍色叉號代表未進、菱形代表待確認結果；修改逐球判定時，記號和各區命中率會同步更新。

沒有球場點、只有一點、未錄影或無法回看時，會保留實際的進／未進結果並將位置列為待定位，不會自動套用人物參考位置。換新影片、重新開相機或拍攝方向改變時需重新完成設定；固定鏡頭可沿用同一組設定。鏡頭移動時請主動重設。分析後仍可修正設定：既有影片定位點會重新換算，重新判定進／未進或補找位置則再次按「開始分析」。

### 人物參考點與非標準場地

預設只顯示到「三分線附近」，中場線不需入鏡。顯示範圍可切成「完整半場」；裁短顯示不會刪除較遠的投籃，範圍外有點時會提示切換查看。校正只使用看得到的地標，不必加入中線點。

在校正中按「＋ 目前人物位置」，先點影片中此刻人物的腳下，再到球場圖點他站的大約位置；也可按「自動找此刻腳下」，確認影片中的 P 標記後再點球場圖。人物不必正在投籃或抬手；辨識到多人、腳部不清楚或模型無法載入時，可直接手動點選。人物點以 **P1、P2** 標示，會和其他地面點一起參與校正；不會將所有球都放到此刻人物的位置。請選雙腳著地的畫面，避免以跳起來的腳當地面。

「＋ 自訂地面點」可用任意清楚的地面位置作參考，例如地磚交點或非標準場地的線角。操作順序相同：先影片、再球場圖，以 **G1、G2** 標示。參考點會記錄原始影格時間、畫面座標、示意圖位置與人工／模型來源，隨校正一起保存；若還沒配對完可按「退回一點」，按取消可保留先前完成的校正。

勾選「非標準場地 · 相對位置」後，使用簡單示意格線並由你指定人物與自訂地面點的位置。區域統計改為圖上左側／正面／右側，CSV 改用相對百分比；JSON 保留示意格座標與 `courtProfile.relative` 標記。此模式不推算實際公尺或二／三分位置，人物在圖上的位置本身也是人工估計。相對模式的百分比以完整示意圖為基準，切換顯示範圍不會改變已存座標。

校正使用全部已配對點：**1 點僅保存參考；2 點做方向與比例粗估；3 點做平面近似；4 點以上以全部點擬合透視轉換**。只有一點時，分析會先完成計數，位置列為待定位；補點後可重新分析，或在分析後手動重試辨識出手點。少點無法完整解出透視，遠離地標的誤差較大；兩點粗估方向不符時可切換「少點粗估時反轉方向」再完成。點分布退化成一直線時會降為粗估並註明品質；互相矛盾、過近或重複的點會要求調整，不會靜默忽略後來的點。籃板與籃圈不能代替地面校正點。

自動定位以 [MediaPipe Pose Landmarker](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker/web_js) lite 模型找每球到框前的身體、抬手與腳部線索，取接近出手時、腳部較低且穩定的影格作為估計。模型在瀏覽器執行；SDK 固定 `@mediapipe/tasks-vision@0.10.32`，WASM 由 jsDelivr、模型由 Google 的 MediaPipe 模型儲存庫下載。需要可回看的影片；即時練投請同時錄影，結束後再校正與定位。**自動位置屬於待複核的近似估計**：跟隨動作、遮擋或多人可能造成錯誤，目前尚無出手／落腳位置的獨立精度驗證。沒有清楚腳部、多人同時疑似出手、沒有穩定線索或換算超出半場的球，會保留待定位。

實際的 70 秒三分影片已使用真實模型跑過全部 31 筆投籃紀錄，產生 21 個腳下位置候選、10 筆待定位；這是線索覆蓋數量，並非位置準確率。1–5 點換算、取消載入、模型錯誤與人工位置保護有控制測試，手機觸控以瀏覽器模擬驗證，尚未在真實 iPhone 上驗證效能與精度。

若地板、腳部或足夠的球場線不在畫面內，可按「直接在圖上標記」，手動估計出手位置，不需先校正。也可選一球，拖曳影片進度或用 ±0.1 秒微調到起跳前，再按「點影片腳下位置」點雙腳之間的地面。重做校正會重新換算已記錄的影片定位點，並將自動點重新標為待複核；圖上人工估計的點不會移動。

位置、定位影格、校正資料隨練習紀錄保存在本瀏覽器，並包含在 JSON 匯出中；CSV 也增加位置座標與來源欄位。重新載入歷史紀錄可看位置圖，但影片需另存，目前不會自動連回原影片。未標位置的球不列入區域統計；待確認不列入命中率，忽略事件不顯示在圖上。

標準參考模式使用 [FIBA 2024 規則的半場線條](https://assets.fiba.basketball/image/upload/documents-corporate-fiba-official-rules-2024-v10a.pdf)；舊式梯形禁區、非標準球場或鏡頭畸變可能造成偏差，可改用相對位置模式。標準參考模式的座標單位為參考公尺，X 從球場中央往圖上右側為正，Y 從底線朝中場增加，並非精密測量。鏡頭移動或拍攝方向改變後須重新校正。地面對應點使用平面透視轉換，原理參考 [OpenCV homography 說明](https://docs.opencv.org/3.4.19/d9/dab/tutorial_homography.html)。

## 本機版本

需求：Python 3.10+、Node.js 18+、FFmpeg。

```powershell
python -m pip install -r requirements.txt
python server.py
```

開啟 <http://127.0.0.1:8765>，或在 Windows 雙擊 `start.cmd`。本機版本可匯入最多 2GB 的 MTS、M2TS、MP4、MOV、M4V 或 WebM，轉檔及輸出存於被 Git 排除的 `artifacts/`。

本機服務 v2.1 會在每次工作開始前重新載入分析引擎，並禁止同一網址重複啟動服務。頁面會顯示實際的本機引擎版本。從舊版升級時，第一次必須關閉原本的 `start.cmd` 視窗再重新啟動；只重新整理網頁不會更新已經載入記憶體的舊 Python 程式。偵測到 v1 服務時，新頁面會提示重啟，並暫時使用瀏覽器分析 MP4 / MOV。

v2.3 前端新增 `court.js`，搭配本機服務 v2.2。從舊版本更新時，請關閉原本服務後再執行 `start.cmd`；只重新整理無法更新舊服務的資源清單。服務 v2.2 可從本機 `artifacts/uploads/` 恢復已轉檔影片與完成的分析，既有影片網址在重啟後仍可使用；尚未完成的轉檔或分析不會自動接續。

電腦的 localhost 可測試相機。iPhone 請用 GitHub Pages 的 HTTPS 網址；普通區網 HTTP 位址不能開啟 Safari 相機。

## 開發與發布

前端位於 `app/`，本機服務是 `server.py`。`app/tracker.js` 的事件規則共用於瀏覽器與本機影片分析。

```powershell
node --check app/app.js
node tests/tracker.test.cjs
node tests/court.test.cjs
node tools/build-pages.cjs
node tests/pages.test.cjs
python -m http.server 8771 --bind 127.0.0.1 --directory dist
```

`tools/build-pages.cjs` 只將明確允許的前端檔案放進 `dist/`，並啟用純瀏覽器模式。所有資源採相對路徑，支援 GitHub Pages 的專案子目錄。

推送 `main` 上的前端、建置工具、Node 測試或部署流程變更後，GitHub Actions 會自動檢查、建置與部署。也可在 Actions 的「Deploy GitHub Pages」手動執行。README 或本機 Python 服務的單獨變更不觸發網頁部署。

首次設定 Pages 時，儲存庫的 Settings → Pages → Source 應選 **GitHub Actions**。

## 辨識限制與測試

目前為固定鏡頭、單一橘褐色或深紅色籃球、有籃網場景的規則原型，沒有訓練通用物件偵測模型。影片校準測試與模擬相機流程已通過；尚未完成真實 iPhone Safari 的效能與準確率驗證，也未建立跨球場的獨立測試資料集。

v2 支援深紅色球、低影格率下快速穿框、間隔少於兩秒的連續投籃，以及影片末尾已有清楚反彈證據的未進球。不要求球在籃網中停留固定時間；球由籃圈內側向下通過，且在籃網下方再次出現，才作為進球線索。部署檔案帶有內容版本碼，更新後可載入新規則。

- 只會記錄偵測到球接近籃框的事件；畫面外、偏離籃框或被遮擋的出手可能漏算。
- 球在籃網區持續向下的軌跡作為進球線索；可見反彈或從通道外落下作為未進線索。
- 結尾、影格中斷或證據不足時保留為待確認，不直接算未進。
- 命中率分母為「進球 + 未進」，不含待確認或忽略事件。所有結果可修正，也可補記漏掉的球。
- 鏡頭晃動、球色、光線、多顆球、籃網遮擋與影格率都會影響結果。

事件規則及部署檢查可直接用 Node 執行。`tests/api_check.py` 與 `tests/browser_check.py` 是額外的本機測試，需自行提供未納入儲存庫的測試影片；`tools/prepare_test_media.py` 可從 `artifacts/source.mp4` 產生所需片段。
